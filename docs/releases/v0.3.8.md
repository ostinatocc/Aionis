# Aionis v0.3.8 Exact Guide-Feedback Attribution Candidate

Aionis Runtime v0.3.8 is a corrective Local Runtime Public Beta candidate for
one self-hosted process. It separates continuity visibility from learning
feedback authority while preserving the evidence-gated learning substrate.

The immutable v0.3.7 tag failed external package smoke before image build
because the old smoke treated a context-only handoff as actually used memory.
Runtime correctly rejected the feedback. No v0.3.7 Runtime GitHub Release or
Docker image was published; v0.3.8 is the new candidate.

## What Changed

- Added top-level host-only `feedback_attribution_v1` to guide responses.
- Builds the attribution projection from post-append SQLite readback in the
  same transaction as the guide exposure and operation receipt.
- Represents persisted authority as an explicit `available`/`unavailable`
  union with exact items, served surfaces, canonical identity, and digests.
- Added SDK parsing and identity validation for the complete attribution
  envelope.
- Made `feedbackFromGuide()` accept only exact host-observed IDs present in the
  persisted projection and derive their served surface.
- Rejects AgentContext-only, unknown, duplicate, mixed-surface, rehydrate-only,
  missing-projection, unavailable-projection, and explicit-assertion fallback
  feedback locally.
- Requires a canonical verified `host_use_receipt_v1` for non-neutral
  `inspect_before_use` or `do_not_use` feedback.
- Removed Host Integration's implicit fallback from missing actual-use IDs to
  all visible `last_use_now_memory_ids`.
- Updated cross-package smoke, public examples, and release gates to use IDs
  recorded by an instrumented Agent/host trace.

## Contract Boundary

AgentContext says what the Agent was allowed to see. It is useful for prompt
construction, continuity, incident replay, and trace correlation. It does not
prove that the Agent dereferenced every visible item and cannot authorize
learning feedback.

`feedback_attribution_v1` says which exact persisted guide exposure items are
eligible for feedback and records their served surfaces. Actual use still comes
from the host's execution instrumentation. SDK feedback requires both.

Cached guides created before this contract must be refreshed. The SDK does not
fall back to AgentContext if attribution is missing or unavailable.

## Safety Posture

- Global admission-candidate serving remains off by default.
- Legacy unprotected feedback is compatibility-only and promotion-ineligible.
- Candidate policy remains calibration-gated and production external policy is
  not registered.
- Durable learning-control queue/worker processing and later promotion phases
  remain outside this checkpoint.
- The supported deployment is one self-hosted Runtime process; multi-instance
  HA and managed multi-tenant GA are not claimed.
