## Follow-Up Found During Verification

In no-key mode, these scripts did not expose actionable memory after a local
write:

```bash
npm run -s runtime:quickstart:http
npm run -s runtime:quickstart:sdk
```

Observed failures:

- `HTTP guide did not expose actionable memory`
- `SDK quickstart guide did not expose actionable memory`

Interpretation:

- This is not a Runtime startup failure.
- The no-key path works for governed external candidates, MCP smoke, and AIFS.
- Stored-memory semantic recall requires an embedding provider.
- The installer should avoid presenting SDK/HTTP quickstarts as the default
  next step for a no-key install, or those quickstarts should gain a no-key
  fallback path.

Recommended next fix:

1. Do not run any demo by default during setup.
2. Keep SDK/HTTP quickstarts as optional embedding-enabled verification loops.
3. Update `aionis` and `@aionis/create` output so the install path points users
   to Runtime startup and Agent integration commands first.

Status:

- Addressed by the `aionis@0.3.1` and `@aionis/create@0.3.1` installer patch.
- Default setup now installs Runtime for real Agent use and skips demos.

## Verdict

v0.3.0 release artifacts are installable and the local Lite Runtime starts from
the public release path. The no-key first-value, MCP smoke, AIFS, Docker,
GitHub release, and npm package train are aligned.

The main release follow-up became the v0.3.1 installer UX patch: setup should be
an Agent integration path, not a demo launcher.
